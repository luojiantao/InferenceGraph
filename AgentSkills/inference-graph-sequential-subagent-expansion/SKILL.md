# InferenceGraph Sequential Subagent Expansion

仅在用户显式调用 `/skill:inference-graph-sequential-subagent-expansion` 时执行本技能。调用中省略的运行参数会按“缺参自动生成与安全默认值”补全；保留用户显式提供的参数，不会擅自覆盖。

本技能采用“协调者串行调度，fresh Worker 单节点单步入图”的方式反向展开已有 InferenceGraph 节点：每个节点都由一个新的子 Agent 独立处理；协调者等待该 Worker 完成，读取图中的实际结果，再决定下一个节点。Worker 之间不共享会话上下文，不并行写图，也不递归启动 Worker。

```text
协调者选择一个当前节点
  -> 启动一个全新的 Worker
  -> Worker 只完成该节点的一层反向展开并退出
  -> 协调者核验实际图状态并更新队列
  -> 启动下一个全新的 Worker
```

图服务是跨 Worker 的唯一事实来源。不要把前一个 Worker 的推理文本、猜测的顶点 ID 或未提交计划当作下一个 Worker 的状态。

## 输入与范围

调用可提供以下参数。除明确标注的例外外，未提供的参数按本节的自动补全规则生成；显式提供但不合法、找不到或彼此冲突的值必须报错，不得静默替换为其他图或节点。

- `sessionId`：已有 InferenceGraph 会话 ID。省略且也未提供 `vertexId` 时，自动新建一个受限会话。
- `vertexId`：根节点 ID 或会话内 `Vn` 引用。省略时，使用已有会话返回的实际 Goal 顶点；自动新建会话时使用服务实际返回的 Goal 顶点。
- `agentId`：本次编排运行的稳定 ID 前缀。省略时自动生成。
- `maxDepth`：展开层数，根节点为第 1 层；`1` 只展开根节点，`3` 最多展开根节点及其后两层 State 前沿。
- `maxNodes`：本次运行最多展开的节点数；可填正整数或 `unlimited`，省略时为 `unlimited`。
- `maxEdges`：本次运行最多创建的 Candidate 边数；可填正整数或 `maximum`，省略时为 `maximum`。
- `maxRetriesPerNode`：因 revision 变化重新委派同一节点的最大次数。
- `goalLabel`：仅自动新建会话时使用的 Goal 标签；可选。
- `model`：只有用户明确指定 `provider/model` 时才传给子 Agent，绝不自动生成或猜测。

### 缺参自动生成与安全默认值

1. 只补全缺失字段。用户显式指定的 `sessionId`、`vertexId`、限制值或 `agentId` 无效时停止并报告具体原因，不得改用其他会话、其他顶点或新的 ID。
2. `agentId` 缺失时，生成 `ig-expand:auto:<UTC yyyyMMddTHHmmssZ>:<6位小写字母数字>`。整个运行期间复用该前缀；它和派生 Worker ID 均须小于 200 字符且只使用字母、数字、`.`、`_`、`:`、`-`。
3. `maxDepth` 缺失时设为 `10`。`maxNodes` 缺失时设为 `unlimited`，即不施加编排侧节点数上限。`maxEdges` 缺失时设为 `maximum`，在新建会话中解析为服务允许的 `100000` 条边。`maxDepth` 仍是强制停止条件；已有会话保留其现有边预算，除非用户明确要求提高预算，协调者不得自动提高。
4. `sessionId` 和 `vertexId` 都缺失时，调用 `inference_graph_create_reasoning_session`，不传 `sessionId`，让服务生成规范 ID。创建时使用自动生成的 `agentId`、`budget.maxDepth=<maxDepth>`、`budget.maxEdges=<resolvedMaxEdges>`，并设置默认策略 `BFS`。其中 `resolvedMaxEdges` 是显式 `maxEdges` 的数值，或 `maximum` 对应的 `100000`。`goalLabel` 优先取用户提供的 `goalLabel`，其次取调用参数中未被键值解析的自然语言任务，最后取当前用户请求；三者都不可用时使用 `反向展开当前用户请求（自动创建）`。Goal payload 标记 `autoGenerated=true`，后续只能使用服务返回的实际 `sessionId` 和 Goal 顶点 ID。
5. `sessionId` 已提供而 `vertexId` 缺失时，先读取 `inference_graph_get_reasoning_session(sessionId)`，使用响应中实际返回的 Goal 顶点 ID；不要猜测 `V1` 或自行新建根节点。
6. `vertexId` 已提供而 `sessionId` 缺失时，先用 `inference_graph_list_reasoning_sessions` 枚举活动会话，并通过 `inference_graph_get_vertex` 查找该顶点。仅当恰好一个会话实际包含该顶点时才采用它；找不到或匹配多个会话时停止并要求用户提供 `sessionId`，不得新建一个不包含该显式顶点的会话。
7. `sessionId` 和 `vertexId` 都提供时，先读取会话并读取顶点，确认顶点归属、类型与规范 ID。只有服务确认后才继续。
8. 自动生成只解决编排边界，不凭空生成领域前提或把 Goal 当作已证明。默认 Goal 语义不足时，Worker 应返回 `insufficient-context`，而不是编造证据。

典型完整调用：

```text
/skill:inference-graph-sequential-subagent-expansion sessionId=<sessionId> vertexId=V7 agentId=release-expand maxDepth=10 maxNodes=unlimited maxEdges=100000
```

最小调用，自动创建受限会话、Goal、agentId 和预算：

```text
/skill:inference-graph-sequential-subagent-expansion 分析 SCH1 换片握手失败的直接前提
```

`agentId` 必须符合 InferenceGraph ID 约束。协调者为每个 Worker 派生可审计的写入者 ID，例如：

```text
<agentId>:step:<stable-sequence>:attempt:<n>
```

保持长度不超过 200，并只使用字母、数字、`.`、`_`、`:`、`-`。派生 ID 用于该 Worker 的所有图写入；不要复用其他 Worker 的 lease 或声称拥有其写入过程。

## 不可违反的规则

1. 一个时刻只能有一个 Worker 运行。使用 `subagent` 的单任务模式，等待结果后才启动下一个；不要使用 `tasks` 并行模式或 `chain` 模式。
2. 每个 Worker 只处理一个分配的目标节点，且只做一层直接前提展开。不得递归展开新前提，不得调用 `subagent`。
3. 图中的边永远是 `前提 -> 当前节点`。反向只用于规划。
4. 同一 `propose_inference_edge` 调用的多个来源表示 AND；不同调用表示 OR。不得把一个 AND 公式拆成多个单来源调用。
5. 下游路径、Goal 可达性或下游结论只能说明当前节点的用途，不能作为当前节点的证据。
6. Worker 只允许执行该节点单步展开必需的 InferenceGraph 读取、创建/复用顶点、提出候选边，以及为不同边设置必要问题的更新。不得 claim、release、answer、complete、block、finish 或 delete。
7. 每个 Worker 的所有写入必须串行，且下一次写入使用上一次响应返回的最新 `graphRevision`。
8. Worker 遇到 `RevisionConflict` 时停止并报告，不要在旧上下文中反复重试。协调者重新读取图后，如仍有必要，才创建新的 fresh Worker 重试。
9. 协调者只从服务实际返回的顶点、边、公式和 revision 推进队列；不能使用 Worker 预测的 ID 或未提交计划。
10. 不要把 Candidate 边、未完成公式或 Worker 计划描述为已证明的结论。

## 协调者职责

协调者是唯一的调度器和队列所有者，不替 Worker 做领域推理，也不把完整 Worker 输出持续堆积在主会话中。

维护以下运行状态：

```text
visited: Set<(sessionId, canonicalVertexId)>
queue: [{ vertexId, depth, reason, attempts }]
expandedNodeCount
createdEdgeCount
latestGraphRevision
stopCondition
```

在启动第一个 Worker 前，先完成参数规范化并只以服务实际返回值推进：

1. 按“缺参自动生成与安全默认值”补齐并记录 `agentId`、`maxDepth`、`maxNodes`、`maxEdges`、`maxRetriesPerNode` 与自动填补字段。
2. 解析或创建 `sessionId` 与规范化根 `vertexId`：自动创建时调用 `inference_graph_create_reasoning_session`，已有会话时调用 `inference_graph_get_reasoning_session`，并且只采用服务返回的 Goal/顶点 ID。
3. 调用 `inference_graph_get_reasoning_session(sessionId)`，读取当前 `graphRevision`、会话状态与边预算；确认会话的可用边预算不少于本轮仍可创建的边数。若预算不足，停止并报告；不要自动提高预算。
4. 调用 `inference_graph_get_vertex(sessionId, vertexId)`，确认根节点存在、归属正确且类型是可展开的 `State`、自动创建的 `Goal` 或用户明确要求继续展开的 `Goal`。
5. 将规范化根节点以 `depth=1` 放入队列，初始化 `visited`、节点/边计数和停止条件。
6. 使用已访问键和规范化顶点 ID 防止重复调度。

## 单节点 Worker 委派

每次从队列取出一个节点时，先检查：

- 尚未访问；
- `depth <= maxDepth`；
- 未达到已设置的 `maxNodes`、`maxEdges` 或用户终止条件；
- 该节点是尚需支持的 `State`、本技能自动创建的 `Goal` 或用户明确指定继续展开的 `Goal`；
- 不是直接 `Evidence`，也不是用户认可的基础状态；
- 该节点未被最新图状态中的完整已完成公式充分支持。

然后使用一次单任务 `subagent` 调用，固定使用用户级 `worker` Agent：

```json
{
  "agent": "worker",
  "agentScope": "user",
  "cwd": "<当前工作目录>",
  "task": "<下方定义的单节点任务>",
  "model": "<仅在用户指定时传入>"
}
```

每一次这样的调用必须等待结束后才能选择下一个节点。不要在同一个 Worker 中塞入多个目标，也不要将一个 Worker 的输出传给下一个 Worker。

### Worker 任务模板

向每个 Worker 提供一个短且完整的任务包。除运行范围外，不要附带前一 Worker 的长篇推理或未验证结论。

```text
任务身份：InferenceGraph 单节点单步展开 Worker
分配目标：sessionId=<sessionId>，vertexId=<assignedVertexId>
写入者：agentId=<derivedWorkerAgentId>
范围：只对该目标执行一次单步反向展开；不得递归展开任何新前提。

开始前，加载并严格遵守已安装的 `inference-graph-backward-expansion` Skill。若该 Skill 尚未进入当前上下文，优先从当前 Agent 已发现的同名技能位置读取其 `SKILL.md`；仅当当前项目携带本分发包且尚未安装时，才回退读取 `AgentSkills/inference-graph-backward-expansion/SKILL.md`。
该 Skill 被配置为仅显式调用，不能假定它已自动进入你的上下文。

固定语义约束：
- 先读取 reasoning session、目标的上游 context 和 downstream context。
- downstream context 仅用于理解目标用途，不是目标证据。
- 规划直接前提；Evidence 是可追溯直接材料，State 是仍需推导的命题。
- 同一公式中的前提为 AND，不同公式为 OR。
- 只创建/复用前提并创建前提 -> 当前节点的 Candidate 边。
- 每次写入后使用最新 graphRevision。
- 发生 RevisionConflict 时立即停止并返回 revision-conflict；不要自行重试。

禁止：处理任何其他 vertexId、递归、调用 subagent、文件编辑、普通 shell 副作用、claim、取证、complete、release、block、finish、delete。

只返回紧凑 JSON，不要返回长篇推理：
{
  "status": "committed | no-op | already-supported | terminal | revision-conflict | insufficient-context | error",
  "targetVertexId": "<服务解析后的规范 ID>",
  "workerAgentId": "<derivedWorkerAgentId>",
  "initialGraphRevision": 0,
  "finalGraphRevision": 0,
  "createdVertices": [{"vertexId":"...","kind":"State | Evidence","referenceId":"Vn"}],
  "reusedVertices": [{"vertexId":"...","kind":"State | Evidence","referenceId":"Vn"}],
  "formulae": [{"formulaId":"...","edgeIds":["..."],"sourceVertexIds":["..."],"targetVertexId":"..."}],
  "formulaeAreAlternatives": true,
  "nextStateVertexIds": ["<本次实际创建或复用且可继续展开的直接 State>"],
  "risks": ["<最多几条具体不确定性>"],
  "stopReason": "<status 不是 committed 时的原因>"
}
```

`worker` Agent 具有通用能力，因此上述任务边界必须原样保留。协调者仍须在结果后直接读取图，不能把 Worker 自报结果视为唯一依据。

## Worker 返回后的核验

每个 Worker 完成后，协调者先解析其结构化结果，再直接调用：

1. `inference_graph_get_reasoning_session(sessionId)`，更新真实 `latestGraphRevision` 与剩余预算。
2. `inference_graph_get_context_for_vertex(sessionId, targetVertexId)`，确认目标、前提和入边的实际状态。
3. 必要时调用 `inference_graph_get_vertex`，确认 Worker 报告的顶点确实存在且类型正确。

按状态处理：

- `committed`：仅从服务确认的直接 `State` 前提生成后续候选节点；更新已访问集合、节点/边计数和 revision。
- `no-op`、`already-supported` 或 `terminal`：标记该目标已处理，不产生新的 Worker。
- `revision-conflict`：重新读取目标上下文；若目标仍需展开且 `attempts < maxRetriesPerNode`，把该节点以递增 attempt 放回队列，并在稍后启动一个全新的 Worker。否则报告冲突。
- `insufficient-context` 或 `error`：不猜测前提，不自动让其他 Worker 覆盖该节点；保留为剩余前沿并记录原因。
- JSON 无法解析或与图实际状态不符：将该 Worker 视为失败，依据直接图查询决定是否重新排队；不要采用它的计划。

每次成功的 `committed` 后，按稳定顺序排列新前沿，例如 `depth` 升序、规范化 `vertexId` 升序。下一节点只能在此核验完成后选择。

## 队列与停止条件

根节点为第 1 层。新产生且可继续展开的 `State` 前提进入下一层。达到以下任一条件时停止，不再启动 Worker：

- 队列为空；
- 下一节点深度超过 `maxDepth`；
- 达到已设置的 `maxNodes`、`maxEdges` 或 InferenceGraph 会话预算；
- 用户指定的语义终止条件满足；
- 会话结束、用户中止或发生无法恢复的 MCP 错误；
- 所有剩余分支都已落到 `Evidence` 或用户认可的基础状态。

不要把“当前队列为空”与“目标已被证明”混为一谈。Candidate 结构仍需另一个从底层到上层的执行阶段来取证、claim 和 complete。

## 上下文卫生与报告

Worker 是 fresh context，但其结果会回流协调者。为避免协调者再次被历史展开污染：

- 要求 Worker 只输出上面的紧凑 JSON，避免重复 context 和完整思维过程。
- 协调者只保留每一步的摘要、实际 `graphRevision`、服务确认的 ID 和剩余前沿；详细事实以图服务为准。
- 下一个 Worker 的任务只带固定语义约束、当前目标和用户范围，不拼接之前 Worker 的原始输出。

结束时输出：

```text
## 串行子 Agent 反向展开结果

### 输入与范围
- 实际 `sessionId`、根节点、`agentId` 前缀、`maxDepth`、`maxNodes`、`maxEdges`、重试上限和停止条件
- 自动创建或补全的字段、默认 Goal 标签和服务返回的规范 ID

### 单步记录
- 顺序号、目标节点、Worker 写入者 ID、状态
- 实际创建/复用顶点、公式组、Candidate 边、提交后 revision
- RevisionConflict 重试、去重、跳过与失败原因

### 停止与剩余前沿
- 已展开节点数、创建边数、最终 graphRevision
- 停止条件
- 未展开 State 节点及原因

### 约束确认
- 每个节点由一个 fresh Worker 串行处理
- 没有并行 Worker、没有 Worker 递归、没有 claim/取证/complete 等执行阶段操作
```
