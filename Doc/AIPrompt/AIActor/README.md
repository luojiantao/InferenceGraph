# AI 角色索引

本文件是本仓库**可用角色索引的唯一事实来源**。方案文档的 `阶段角色与职责` 表必须使用下表「角色文档」列中的精确索引名。

角色只提供身份、核心职责、判断视角、工作方式和职责边界，边界定义见 [AI提示词六要素设计指南](../AI提示词六要素设计指南.md)。角色不携带技术栈、领域知识、任务需求、执行约束或验收标准。

## 角色索引表

| 角色文档 | 显示名称 | 适用阶段 | 一句话职责 |
| --- | --- | --- | --- |
| [architect](./architect.md) | 架构师 | 代码阅读、边界确认、方案与现状核对 | 判定边界、依赖方向和结构风险，不写实现代码 |

## 使用规则

1. 方案的每个必要阶段都必须指定一个索引，且 `阶段角色与职责` 与 `实现步骤` 中的索引必须一致。
2. 执行方在进入每个阶段前必须完整读取该角色文档，确认职责覆盖该阶段。
3. 同一索引可覆盖多个符合其职责的阶段，但不得因此扩大角色边界。
4. 不得延续上一阶段的角色；阶段切换时重新确认当前角色与输出重点。
5. 索引缺失、不存在、被显示名称代替、前后不一致，或角色职责无法覆盖阶段职责时，必须**在修改任何文件前停止并询问用户**，不得自行创造、近似替代或使用默认角色。
6. 新增角色时同步更新本表，并保证新角色职责与现有角色不重叠。
